## What the diff does NOT do that the spec/decisions require

- **`codex-agents/checker.toml` drops a clause that `agents/checker.md` keeps, and the parity
  test does not notice.** `agents/checker.md` ends its P4 sentence with: "A red test is
  CHANGES-REQUIRED unless `comm` shows it red on the base too — **a name absent from the base
  counts as not-red-on-base, so its red on the branch is new**." `codex-agents/checker.toml`'s
  equivalent sentence stops at "...unless comm shows it red on the base too." — the clarifying
  half-sentence is simply absent from the Codex twin. I confirmed this is a real gap, not a
  formatting artifact, by reading both files at `fcf4696` directly (not just the diff hunks).
  This is exactly the class of gap the review checklist's item 3 ("`.md` and `.toml` twins say
  the same thing for both roles") and item 4 ("a test absent on the base must count as not red on
  the base — check the doctrine does not leave this open") ask me to catch, and it fails both: the
  doctrine states the "absent = not red" rule for the Claude-side `checker` but leaves it unstated
  for the Codex-side one.
- **The parity regex cannot catch this gap** (checklist item 5, "try to break the parity regex").
  `INVARIANTS.checker` in `codex-agents/parity.test.js` checks only
  `/merge-base[\s\S]{0,350}(comm -23|never by count)/i`, which matches on the presence of
  `merge-base` followed within 350 chars by either `comm -23` or `never by count` — it says
  nothing about the "absent from base" clarification. I ran this regex against a hand-built
  string shaped exactly like the current `checker.toml` sentence (present, minus the "absent"
  clause) and it returns `true` — the automated gate is silent on precisely the sentence this diff
  silently dropped. I also confirmed the regex is breakable in the direction the checklist names
  ("drops the rule but passes it"): a decoy string that mentions `merge-base` and `never by count`
  for two unrelated purposes 200 characters apart also matches. (Scratch-only test, not committed;
  not run against any repo file.)
- **The Q7/R5/F3 "same procedure" question for `checker` is answered narrowly, and defensibly, but
  the diff does not say so.** P4.3's "Ta sama procedura" could be read as including qa's step 4 (record
  red-on-base to the run log's `Known-red:`), not just the comm-based CHANGES-REQUIRED test. This
  diff gives `checker` only the comparison/CHANGES-REQUIRED half and leaves `Known-red:` writing to
  `qa`/the run log alone (consistent with the P4 file table, which does not list `checker.md` under
  P4.1's `Known-red:` requirement). I read this as the correct reading — `Known-red:` is a single
  push-scoped list that "expires after the push" (P4.1), so a per-phase gate role writing into it
  ahead of push would be premature — but the diff never states the reasoning, so a future reader
