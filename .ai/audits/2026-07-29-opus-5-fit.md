# Audit: does this framework still fit the model it runs on? (Claude Opus 5)

Date: 2026-07-29 · Scope: `AGENTS.md`, `agents/*.md`, `skills/`, the frontmatter validator
Source: the `claude-api` skill's model + migration reference (authoritative for model facts;
this audit does not restate API details the framework never calls).

**Read the scope line before the findings.** This repo is a Claude Code framework, not an
application that calls the Messages API. Every API-surface change in the Opus 5 migration —
thinking defaults, sampling parameters, `max_tokens`, fallbacks, task budgets — is **out of scope
by construction**: nothing here constructs a request. What *is* in scope is the behavioral half,
because this repo's entire product is instructions aimed at the model, and Anthropic documents
specific behavioral shifts that those instructions were not written against.

## Verdict

**No defects. Three gaps worth closing, one open measurement, and one misreading to guard
against.** The framework has already absorbed the sharpest Opus 5 change on its own.

## Gaps

### G1 — the length rule covers answers, not files *(recommend closing)*

`## Answer shape` governs what reaches the human in conversation. Anthropic documents a **separate**
Opus 5 tendency: **files written to disk run long** — reports, Markdown, summaries — and it carries
its own recommended instruction distinct from conversational conciseness.

This repo's output is almost entirely files. Specs, evals, verdicts, `STATE.md`, `CHANGELOG.md`,
run logs, commit messages. The rule as shipped does not reach any of them.

Evidence from this session, which is not cherry-picked — it is the only session run under the new
rule: the answer-shape VERDICT is 60+ lines, the trigger-collision map is a full document, and
several commit messages run 15–25 lines. The conversational rule held; nothing governed the files.

**Proposed:** extend the section with the deliverable-length clause — cover the substance, no filler
sections, no redundant summaries, no boilerplate. One paragraph, both copies.

### G2 — scope discipline exists only as a gate, never as a rule *(recommend closing)*

Opus 5 is documented to expand task scope and to apply its own judgment about what the task should
be without flagging it. The framework catches this **downstream**: `checker` grades for scope creep
(`agents/checker.md:17`), and `sailes-implement`, `sailes-database` and `sailes-discovery` all name
it in review checklists.

Nothing tells the **maker** roles not to do it in the first place. Under a model that expands scope
more readily, that shifts load onto a gate that was sized for a model which did it less. A gate is
the right backstop and the wrong only line of defence.

**Proposed:** a scope clause in the maker roles (`be-dev`, `fe-dev`, `designer`) or once in
`AGENTS.md` — deliver the asked-for scope, make routine judgment calls, name the disagreement in a
sentence and continue rather than quietly widening or narrowing.

### G3 — nothing governs self-correction narration *(recommend closing, lowest cost)*

Opus 5 flags and explains its own earlier mistakes at length. In this framework that noise
compounds: a worker narrates a correction in its report, the lead reads it, and the lead's summary
to the human carries it forward. Anthropic's recommended instruction explicitly scopes correction
to errors that change the reader's decisions, and explicitly exempts thinking blocks.

**Proposed:** two sentences appended to `## Answer shape`, and a matching line in the worker roles'
Report sections if G2 lands there anyway.

## Open measurement — effort pins predate the models they run on

| Role | Model | Effort | Guidance for that model |
|---|---|---|---|
| `team-lead`, `researcher` | `claude-opus-5` | `high` | Start `xhigh` for coding/agentic, `high` elsewhere; then sweep down — `low`/`medium` are unusually strong on Opus 5 |
| `be-dev`, `fe-dev`, `tester`, `qa`, `checker`, `designer` | `claude-sonnet-5` | `high` | Keep `high` as default; raise to `xhigh` for the hardest coding/agentic work |
| `docs-author` | `claude-sonnet-5` | `medium` | Deliberate (spec D3: the validate loop is deterministic) — no change indicated |
| `explorer` | `claude-haiku-4-5` | — | Correct; no effort parameter on Haiku |

Both models' guidance says effort matters **more** on them than on any prior model in their tier,
and that prior-model defaults rarely transfer. Every pin here says `high`, which was set before
either model existed.

**This is a measurement, not a finding, and it is deliberately not a recommendation.** The framework's
own rule (`evals/lead-proposes-a-measurement-when-it-cannot-recommend.md`) applies to me here: I have
no eval data on `xhigh` for these roles, and guessing a pin that ships to every repo on every machine
is exactly the move that rule exists to prevent. What would settle it is a sweep of `medium`/`high`/
`xhigh` for `be-dev` on a fixed task with the `checker` verdict as the score.

## A live backlog item now runs against the guidance

The 2026-07-28 eval batch produced promotion candidate 1: *"`delta-at-gate.md` could tell the lead to
spot-check that the receipt reproduces before showing it to the human."* It came from real observed
behavior and reads like good rigour.

Anthropic's Opus 5 guidance points the other way, and unusually firmly: instructions that **tell**
the model to verify now cause **over**-verification, and *"removing them reduces over-verification
with no capability regression — this is a delete, not a rewrite."* The same note says harness-level
verification steps carried from prior models are likely redundant.

Note this **inverts a standard prompting best practice** — "ask the model to self-check" is normally
sound advice and is specifically wrong on this model. A rule library that applies it uniformly needs
a carve-out rather than a global habit.

**Recommendation: re-examine that candidate before it lands**, and note in `backlog.md` why it is
being held rather than letting it look forgotten. Worth knowing that the eval which produced it also
recorded the agent doing the spot-check *unprompted* — which is the guidance's own point: the
behavior is already there, so writing it down buys nothing and risks the over-verification tail.

## The misreading to guard against — `checker` and `qa` are NOT self-verification

The guidance above is about **a model re-checking its own work in its own context**. It is not about
independent review, and applying it to this framework's gates would be a serious error.

`agents/checker.md:9` states the mechanism plainly: the protection is **input isolation** — the
checker receives only the diff, the spec, and the checklist, and must not receive the maker's report
or reasoning. Its own description says it *"grades the artifact, not the story."* That is a
structural property of what the reviewer is allowed to see. No model improvement changes it, because
the failure it prevents — a maker grading its own work with its own narrative in context — is not a
capability gap.

The same holds for the `VERIFIED` spine rule, which is about **evidence shown to the human**, not
about the model satisfying itself.

**Recorded so nobody later cites the Opus 5 migration guide as grounds for thinning the gates.**
If that argument is ever made, this paragraph is the answer.

## What this audit did not cover

- **Runtime behavior.** Everything here is read from files on disk. Whether the roles *behave* as
  their text says under Opus 5 is what `evals/` measures, and no eval was run for this audit.
- **The Codex twins.** `codex-agents/*.toml` were checked for pin parity by the existing parity test,
  not re-audited for behavioral fit; Anthropic's guidance does not describe the models Codex routes to.
- **Sonnet 5's own shifts**, beyond effort. Six of ten roles run on Sonnet 5, which has its own
  documented behavioral changes (more literal instruction following, more agentic tool use, better
  default progress updates). A separate pass against those is worth doing and was not done here.
- **Whether any of this is worth the change.** Three gaps are named with proposals; none was
  implemented. That is the human's call.
